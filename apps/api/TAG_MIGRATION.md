# 统一标签迁移与恢复运行手册

本文描述0007的人工操作顺序，不代表任何日常或生产库已升级。不要把6171或既有业务库作为测试目标。

## 操作前

1. 确认目标环境、PostgreSQL 18、迁移账号、完整迁移链和不可变包摘要；保留既有发布工具的指定提交、同包、备份和迁移门禁。本次工作目录无提交，验收证据不能作为其他提交的发布证明。
2. 在自己的隔离副本运行 `python -m app.tag_preflight --dsn "<明确目标且不含密码的连接串>"`，输出至私有报告目录。该命令只读，报告包含owner、名称和逐组映射候选，不公开上传；密码使用私有pgpass。报告包括指纹、同账号合并组、来源／规范关联计数、类型／生命周期计数。空名、超80规范名、孤儿或去重后超过30项必须先处理原因再继续，禁止截断／跳过。
3. 选择维护窗口；在隔离副本量测锁等待、扫描、回填与索引时间，给正式窗口预留恢复时间。准备相同统一标签能力且满足既有字节兼容门禁的恢复包。

## 停写、备份、迁移、激活

1. 停止旧应用及其他写入者，保持维护状态。执行既有完整数据库／媒体联合备份，保留清单、摘要、数据库和图片副本；先在独立隔离库验证恢复和应用读取，记录备份ID与时间截点。
2. 再做只读预检并核对报告。使用现有 `app.db_migrate` 命令，以显式目标参数和migrator账号执行完整链。迁移在原表排他锁下重新计算规范名及映射，故不依赖预检文件继续有效；0007的DDL、来源回填、验证、授权和版本记录同事务提交。
3. 迁移核验：每个旧topic/tag在tag_aliases有同owner映射；card_topics及legacy_card_tags的每条旧关系都有对应来源及规范关系；规范关系无多余项；按owner、类型、生命周期对照原内容。账号、会话、卡片ID／修订／幂等摘要、附件、合集顺序、清单条目及完成状态、复习状态保持原值。
4. 新包必须包含0007、能力标记reference-memo-tags-v1和features.unified_tags；只有迁移成功且readiness识别新结构后才激活。本人四类型保存、多选all/any、旧ID／URL／请求重试、两账号隔离和清单／复习回归通过后开放写入。

## 失败与恢复

- 0007失败：保留错误和报告，验证该版本、映射表及新授权未提交，旧表数据仍在；旧包可在确认事务回滚后恢复服务。之前已完成的迁移不反向回滚。
- 迁移成功、激活失败：保持停写。禁止自动回退到旧reference/memo包；先核对真实历史、包清单和当前指针。使用具有相同能力且满足现有API／迁移字节兼容检查的包恢复，或前向修复。原发布仍为失败，恢复成功不改写结果。
- 必须整库恢复：先保存故障库完整副本，明确备份截点、故障后／上线后新增写入和补录计划；在新的隔离库验证数据库／媒体联合恢复、旧URL、来源映射与两账号读写，再由人工决定正式切换。不要覆盖唯一故障副本，不删除映射／来源或把多标签压回单分类。
- 新旧客户端过渡期保留全部别名和来源，快照只读。未来删除兼容接口或清理快照另立OpenSpec变更。

## 本次验收与本机工具

测试使用当前worktree专属6179实例和24568服务，端口占用时拒绝启动，不接管已有实例。`scripts/ci_backend.py` 创建并停止自己的6179／6180实例；`scripts/tag_browser_environment.py` 为浏览器启动自己的6179和24568，结束时停止确切的自有进程／data_directory。二者不能同时运行。

本机发布工具在Git中被忽略，当前worktree只复制了所需无凭据文件；未复制target.local.json，也未修改主仓库工具。统一标签门禁补丁保存在本变更的release-tools.patch，正式使用前由维护者在相应工具项目应用并核验。不要把工具本地模拟测试当作生产已发布。验收结果与截图实际查看记录见[本次验收](../../openspec/changes/archive/2026-10-22-unify-card-tags/validation.md)。
