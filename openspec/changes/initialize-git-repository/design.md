## Context

当前目录已包含 OpenSpec 配置、仅供本地参考的 `docs/` 计划和本地代理技能副本 `.agents/`，但尚不是 Git 仓库。详见 `proposal.md` 的动机与范围。

## Goals / Non-Goals

**Goals:**

- 以最小、安全且可复查的文件集建立本地版本控制基线。
- 让 OpenSpec 工件成为后续协作和审查的共享记录。
- 防止本地计划、代理运行内容以及常见敏感或生成文件进入首个提交。

**Non-Goals:**

- 不创建远程仓库、分支保护、CI/CD、部署配置或应用代码。
- 不修改 Git 用户身份、全局 Git 配置或任何现有本地材料。
- 不将 `docs/` 的计划转化为已批准的项目需求。

## Decisions

### 受控暂存清单

只显式暂存 `README.md`、`.gitignore` 和 `openspec/`，并在提交前检查暂存列表、大小与疑似秘密。相比 `git add .`，该方式避免把当前已知的本地目录或未来新增的未审查内容带入基线。

### 根目录忽略规则

`.gitignore` 将明确忽略 `docs/` 与 `.agents/`，同时覆盖 `.env`、私钥、日志、缓存、构建输出、Python 与 Node 依赖等常见本地内容。不会忽略 `openspec/`；其配置、进行中变更与归档记录都应可在远程仓库中共享。

### 本地提交优先

执行 `git init` 后创建一个本地初始提交，但不设置 remote。远程托管平台、访问权限和推送时机均需后续单独变更与用户授权。

## Risks / Trade-offs

- [忽略规则过宽而遗漏未来应跟踪文件] → 提交前使用 `git check-ignore` 和 `git status --ignored` 检查，并仅允许已审查的显式文件进入基线。
- [未知敏感内容进入提交历史] → 在暂存后检查文件列表和文本中的常见凭据模式；该检查仅降低风险，不能作为不存在秘密的证明。
- [本地计划不进入远程导致缺少备份] → 维持用户指定的 `docs/` 本地范围；待计划成为正式、可审查依据时，再通过独立变更将其纳入 OpenSpec 或受跟踪文档。

## Migration Plan

1. 创建忽略规则与简洁 README。
2. 初始化本地 Git 元数据。
3. 显式暂存并审核批准的基线文件。
4. 创建初始提交并验证工作树、提交内容、忽略规则与 remote 列表。

若审核发现不应提交的文件，在创建提交前将其从暂存区移除并调整忽略规则；本变更不会重写历史或删除用户文件。
