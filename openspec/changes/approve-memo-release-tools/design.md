## Context

既有管理员代理只接受 backup、restart、status，批准摘要覆盖整个 TOOL_FILES。已只读确认三个差异文件，部署密钥无法登录 root；原安装器拒绝覆盖不同内容，不能用于升级。动机见 proposal.md。

## Goals / Non-Goals

**Goals:** 将已通过门禁候选的三个差异工具及其摘要作为一次性固定升级资料交付，保留原文件并在失败时恢复。

**Non-Goals:** 不建立自动自我批准能力，不扩展 sudo，不修改管理员入口、业务数据库或应用候选，不重做已通过检查的构建。

## Decisions

- 所有新字节来自候选冻结 tools 快照；验证其摘要与 manifest 一致，并核对当前工作区工具仍匹配。
- 从服务器读取完整旧配置并固定摘要。升级在 root 私有副本中运行，先验证脚本及资料摘要，逐项验证受保护路径、旧配置及全套旧工具，拒绝状态漂移。
- 升级前将旧配置和三个旧文件保存到独立 root 私有目录；按文件原子替换，最后替换配置。异常则恢复旧文件和配置，不触碰服务运行状态。
- 生成 verify-only 检查入口，可在管理员终端验证资料和前置状态而不写入正式配置。
- 通过部署账号上传私有待办资料，仅由实际管理员复制到 root 私有目录后执行。若无管理员通道，交付已上传资料的具体命令，不声称已升级。

## Risks / Trade-offs

- [缺少 root 凭据] → 保留用户本机输入凭据的边界，交付固定核验命令；不尝试绕过受限代理。
- [替换中断] → 配置最后写入，保留持久旧副本；常规异常自动恢复，进程被强杀时由管理员按旧副本恢复后重新预检。
- [并发管理员操作] → 一次性升级锁；现有代理在混合摘要期间会拒绝操作。选择无发布进行时执行，升级后必须 Doctor。

## Migration Plan

验证候选 → 生成固定资料并检查 → 上传 → 管理员复制、核验、执行 → Doctor → ResumeReleaseId 同包发布。升级只更换批准快照，不执行备份、迁移或重启；发布仍由既有控制器完成全部门禁。

### 工具升级过渡场景

实际升级后发现 Doctor 的旧版本管理员 status 会将旧发布包工具摘要与新批准工具硬比较，因而拒绝旧版本。一次性过渡核验保留 Doctor 的其余所有检查：调用 root 所有且已核验的管理员模块的只读 load_configuration 验证新版批准快照；旧包使用本机已验收旧记录固定的摘要和逐项核验后的旧 executor 校验完整归档、解包文件、stage 状态及实际 current，避免执行未核验代码。此步骤不执行特权写操作。

过渡核验成功后使用已有 publish 分阶段入口，执行同包 Stage、受限代理 Backup、本地下载校验、Migrate、Activate、Status 和 AdminStatus；最后完整 Doctor 必须通过。保留全部既有阶段安全检查与证据，不修改控制器或 root 代理以接受未知工具。
