## Context

README 已是项目概览和文档导航，CONTRIBUTING 与 AGENTS 分别服务贡献者与编码代理。其余五份根文档是独立的操作手册。docs 已被 Git 忽略，保存本机资料，不能作为公开手册的目标目录。此前已经完成产品概览及备份／媒体重复操作的收敛，本次继续整理文件位置，避免重新合成过长的综合手册。

## Goals / Non-Goals

目标：根目录 Markdown 从八份减少为三份，读者仍从 README 一步找到专项手册，迁移后相对文件链接与锚点有效，去掉完全重复的章节。

非目标：不重写运行命令，不调整应用内文档布局，不迁移或修改历史验收记录，不清理本机私有资料，不改变运行和发布行为。

## Decisions

- 使用 handbook/ 保存五份现有手册，保留文件名和标题，使 Git 能识别迁移且减少引用变更。通过根 README 的现有表格导航，不新增重复目录页。
- 对迁移文档中的根 README、apps 和 openspec 链接增加一级相对路径；同目录专项手册的互链保留原相对目标；应用文档的入链指向 ../../handbook/。
- 命令继续按正文要求在仓库根或指定应用目录执行，文件移动不改变命令语义。
- SOURCE_CAPTURE 中两段同名网络限制章节完全一致，只保留一段，所有操作边界与后续计划保留。
- 不保留根路径跳转占位文档，达到根目录精简目标。历史记录描述当时文件位置，不批量改写历史；当前公开链接全部更新。

## Risks / Trade-offs

外部引用的旧根文件 URL 将失效，仓库内当前链接统一修正；Git 历史仍可查询旧文件。handbook 必须进入 Git 索引后再执行现有文档检查，确保新克隆可访问。纯文档改动，无应用展示影响，视觉审查不适用。
