## Why

SelfLore 当前只支持用于复习的事实知识和独立正文的原子观点，无法自然收纳外部图片、摘录或他人的观点。用户希望保存图片、简单说明和来源，并在采用本地图片存储时获得可排查容量、完整性、访问表现及备份恢复情况的脚本。

## What Changes

- 增加「资料卡」第三种类型，支持原始摘录或图片、独立的「我的说明」、作者／发布者／平台／发布时间等来源信息；收录不代表认同或验证为事实，未知来源允许留空。
- 保留四个主导航，在知识页提供「全部／资料／事实知识」筛选；资料直接阅读，不产生复习单元。新建、检索、分类标签、收藏、链接、合集、主页和游客演示纳入第三类卡片。
- 为资料卡提供文件选择、拖拽、剪贴板图片上传、多图编排、缩略图及原图放大。第一版不开放知识／观点正文内的图片上传，也不加载任意外部 Markdown 图片。
- 图片存独立持久化目录，数据库保存稳定附件身份及关联；会话鉴权读取，保留原图和可再生成的缩略图，程序更新不搬动业务图片。
- 新增按需运行的只读监控排查脚本，输出容量、增长预测、文件完整性、服务端图片请求统计、备份新鲜度及恢复演练信息，提供文本／JSON 报告、阈值建议与退出码。缺少测量数据明确标为未知，不自动清理、迁移或创建定时任务。
- 扩展现有本机数据库备份及隔离恢复流程，形成同一快照对应的数据库＋附件备份包，兼容旧备份；补齐运行配置、Linux 目录写权限和维护说明。

## Capabilities

### New Capabilities

- `card-attachments`: 资料卡图片上传、稳定身份、来源描述、排序、鉴权阅读、本地文件持久化和安全失败。
- `media-storage-diagnostics`: 按需检查图片容量、增长、完整性、请求表现及备份恢复状态，输出有口径的排查报告。
- `media-backup-recovery`: 数据库与附件的一致备份、旧格式兼容和隔离恢复核验。

### Modified Capabilities

- `card-library`: 第三种卡片内容形态、来源字段、分类检索及附件修改冲突。
- `card-workspace`: 新建资料卡、知识页类型筛选和可恢复路由、原始材料与个人说明的展示。
- `card-collections`: 三类混合编排、资料图片阅读和成员计数。
- `opinion-linking`: 观点能够引用资料，资料能够展示及建立双向关联。
- `knowledge-review`: 明确资料不产生复习单元、不进入队列及掌握计数。
- `personal-home`: 独立资料数量及资料活动筛选，上传中间过程不重复计学习事件。
- `card-schema-evolution`: 追加第三类内容、附件与同所有者关系约束，保留已有内容与复习数据。
- `guest-demo-workspace`: 独立的资料示例和打包示例图，游客上传拦截及图片缓存隔离。

## Impact

- 后端：`schemas/workspace.py`、`services/cards.py`／`collections.py`／`profiles.py`、工作区路由、认证读取边界、`main.py`；新增附件存储、遥测及诊断模块。
- 数据库：在现有 0001–0004 之后追加迁移，并更新 `db_migrate.GRANTS`；不修改历史 SQL，不自动执行日常或生产迁移。
- 前端：卡片类型、知识页、新建、详情、选择器、合集、主页、回收站、演示数据；新增独立附件展示组件，保持不受信任 HTML 禁用。
- 运维：本地启动配置、`db_backup.py`、脚本入口、备份格式、systemd 指定目录写权限、发布检查与维护文档。诊断脚本为本项目工具，不是个人全局 skill／hook／automation。
- 依赖：预计新增 Pillow 和 multipart 解析依赖，实施时通过现有 uv 虚拟环境与锁文件管理；不引入对象存储服务或监控平台。
- API 类型枚举新增 `reference`；现有知识／观点请求、稳定 ID、链接和复习状态保持兼容，前端与后端应配套发布。
