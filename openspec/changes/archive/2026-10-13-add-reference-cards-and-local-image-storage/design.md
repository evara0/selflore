## Goals / Non-Goals

**Goals:**

- 让图片型资料在不填写观点、问题或答案的情况下保存并持久阅读，原始材料与个人说明有明确边界。
- 让本地图片的写入、引用、鉴权、备份和恢复构成完整闭环，同时可用只读脚本定位异常。
- 用稳定附件 ID 和相对存储键隔离物理位置，为以后换对象存储留下接口。

**Non-Goals:**

- 本次不实施对象存储／图床／CDN、OCR、AI 摘要、X 内容抓取或自动事实核验。
- 不提供「提炼观点／制作复习卡」快捷动作；现有新建与手动引用已能建立联系。
- 不开放知识／观点的图文编辑，不提供附件永久删除、自动垃圾清理、定时任务、推送提醒或监控仪表盘。
- 不把诊断报告称为浏览器实测，不将云存储视为自动备份替代品。

## Decisions

### 1. 资料作为同一 cards 表的第三类内容

新增 `kind=reference`，`form=NULL`，`question_md`／`answer_md` 为 NULL。`body_md` 保存原始摘录，可为空；新增 `note_md` 保存「我的说明」。资料有效条件为非空原始摘录或至少一个 ready 图片附件；仅标题、来源或个人说明不能代替原材料。图片＋标题可以保存，说明与来源均可选。

新增可选 `source_author`（原帖／摘录作者）、`source_publisher`（发布或转载账号）、`source_platform` 和 `source_published_on`（日期，不虚构精确时分秒）；既有来源标题／URL／定位继续使用。这些来源字段三类卡片均可读写；`note_md` 和附件列表仅资料使用。图片原作者在图片关联的 `creator_name` 中填写，可与来源作者不同。空字段界面按未知处理，不建立「已核实」标记。

所有文本字段沿用 64 KiB 正文限制与 HTTP(S) 来源校验。来源作者／发布者／平台加入 search_text；资料的摘录、说明加入检索，第一版不搜索图片内部文字。沿用创建幂等摘要及修订号，附件集合、顺序、图注修改作为同一次卡片修订提交。

替代方案为知识新增 image 形式或观点加来源归属；前者仍与复习绑定，后者仍要求用户将资料当作观点。独立 reference 类型能直接表达此次收录行为。

### 2. 四导航内组织三类卡片

保留「知识／观点／合集／我的」主导航；知识页默认「全部」，覆盖 knowledge 和 reference，不混入 opinion。提供「全部／资料／事实知识」类型筛选，URL 中保存筛选。后端保持 `/cards?kind=knowledge` 的旧语义，增加与 `kind` 互斥的 `kinds=knowledge,reference` 多类型过滤；无过滤仍返回所有类型。修改类型筛选时清除不兼容分类和页码。

资料采用独立 reference 分类（至多一个），知识分类也仍至多一个；全部视图分类标出类型，选择分类时同步选择对应类型，标签跨三类复用。资料默认待整理，可切换已整理。资料详情拟用 `/knowledge/references/:id`，新建 `/new?kind=reference`，旧知识与观点 URL 不变。

编辑器顺序为标题、原始摘录／图片、我的说明、组织与来源；资料直接展示原始材料和说明，第一张缩略图作列表预览。详情与合集使用同一附件组件，放大支持关闭按钮、Escape、焦点返回、触控滚动及替代文本。移动端不依赖拖拽，提供文件选择和上下移动按钮。

统计新增 `references`／`reference_count`，主页分别显示资料、知识、观点、合集，资料创建及实质编辑沿用学习事件；单独上传或上传重试不写学习事件。资料没有显示答案／评分，不生成调度状态。避免所有 `else` 分支将 reference 误判为 opinion。

### 3. 附件记录与关联独立，文件内容不可变

拟新增 `app.attachments`：UUID、owner_id、storage_backend（首版仅 local）、original_key、thumbnail_key、原图／缩略图字节数及 SHA-256、MIME、宽高、status、上传请求 UUID 与内容摘要、创建时间。`status` 使用 uploading／ready／failed 多状态枚举，不使用含糊 Boolean。已有 `is_bookmarked`、`is_active` 命名及默认值保持兼容，不做无关重命名。

拟新增 `app.card_attachments`：owner_id、card_id、card_kind 固定 reference、attachment_id、position、caption、alt_text、creator_name。使用同所有者复合外键、防重附件和防重位置约束；一个附件可被同用户多个资料卡引用。服务与事务末的延迟约束触发器共同检查资料非空条件以及关联附件必须 ready，直接 SQL 也不能提交空资料、跨用户附件或非资料关联。延迟检查允许在同一事务中完成建卡及关联替换。

移除关联、替换图片、卡片归档或回收站仅改变关系／生命周期，不物理删除已完成附件。替换产生新附件 ID 与存储键，其他引用不受影响。未引用 ready 文件属于可排查的保留文件；第一版不建立全局或跨用户 hash 去重，SHA-256 仅校验与同一请求重试比对。

### 4. 独立本地目录与有限上传

运行配置 `SELFLORE_MEDIA_ROOT` 指定绝对目录；建议本机 `G:\selflore-data\media`、Linux `/srv/selflore/shared/media`，不在 release、web/public、Git 或缓存目录。另设 `SELFLORE_MEDIA_OPS_ROOT` 保存受限遥测和可选诊断报告，建议与媒体目录并列。运行初始化通过明确的配置操作创建目录和环境／数据库标识文件；普通启动与只读诊断不静默创建或修复目录，启动检查标识和路径，诊断核对当前库。

存储键由服务生成，如 `<owner-uuid>/<attachment-uuid>/original.png` 和 `thumbnail.webp`；客户端只能提交稳定 ID，不提交路径。存储适配器提供 put／open／stat，不在业务正文持久化绝对路径、外部 URL 或临时访问 URL。文件读取和扫描解析规范路径并拒绝逃出根目录的符号链接、Windows 重解析点及目录穿越。

首版默认每文件上限 20 MiB、每卡最多 10 图、解码上限 40 百万像素、最长边 20000 像素；支持静态 JPEG／PNG／WebP，拒绝 SVG、动画、伪造或损坏图片。上传流式限量写入受限 staging，校验实际字节和图片格式。保留原始上传字节，另生成最长边不超过 960 像素的 WebP 缩略图，应用 EXIF 方向但不在缩略图保留 EXIF。原图不在列表自动加载。

采用现有 uv 虚拟环境，引入 Pillow 和 python-multipart，由锁文件管理；不新建环境或提前安装依赖。上传限制为运行配置可调整值，界面显示实际限制，诊断输出实际配置。

### 5. 上传及保存的失败边界

拟新增 `POST /api/attachments`（一文件 multipart＋client_request_id），`GET /api/attachments/:id`（本人元信息），`GET /api/attachments/:id/content?variant=original|thumbnail`。原有卡片创建／PATCH 加 `attachments` 有序数组，包含 ID、图注、alt 和创作者。前端上传请求沿用 Cookie、Origin 和 CSRF，不给 multipart 强制设置 JSON Content-Type；资料新建 JSON 的附件数组与修订号逻辑保持一致。

上传请求带文件SHA-256（前端计算，服务端流式校验，不信任声明），先保留 uploading 记录及预期摘要，流式写入本次尝试独占的 staging，校验及生成缩略图后原子发布不可变文件，最后将记录改为 ready。相同 owner＋request_id＋相同文件重试返回原附件；不同文件同标识返回 409。上传期间持有该请求的会话级锁，唯一约束限制登记记录；并发同标识拿不到锁时返回可重试状态，不启动第二份写入。锁随进程中断释放，显式同文件重试可以接管未完成／失败记录：已发布且校验相符的文件可完成登记，否则写新的尝试文件，不覆盖不同内容。进程中断可能留下 uploading 或未登记文件，诊断报告而不自动删除；仅本次仍独占的 staging 在普通失败路径清理。

上传完成才允许参与建卡或编辑。保存时事务验证完整附件集合、ready 状态、所有者和修订号，再更新正文、关系、搜索文本和事件。上传或保存失败保留文字及已成功上传的 ID，禁用「全部成功」反馈；未完成图片必须重试或明确移除后才能提交。退出保留未保存提醒，但不承诺刷新后自动恢复本机 File 对象。

鉴权在读取文件前完成；未登录 401，非本人及不存在 ID 返回相同 404，管理员无额外个人访问权。本人可在回收站／归档详情读取已关联附件；普通列表和合集仍跳过不可用卡片。资源响应 `Cache-Control: private, no-store`、明确 MIME 和 nosniff；不建立公开媒体静态挂载。游客演示图来自打包的通用示例资产，不采用本次用户图片，不请求私人附件 API。注销清理查询数据和 object URL，浏览器已下载／手工保存的副本无法回收。

替代方案是开放 Markdown img 或直接写图片 Base64；前者绕过本地生命周期和访问控制，后者把大文件塞入正文及 JSON。专用附件组件更符合可排查、可备份要求。

### 6. 只读诊断脚本与测量数据来源

实现可跨 Windows／Linux 使用的 `app.media_diagnostics` CLI，Windows 根入口拟为 `check-media.cmd`＋`scripts/check-media.ps1`。本机入口加载既有本地配置及凭据，不读取或输出迁移密码；核心 CLI 使用 app 角色只读事务并核对显式预期环境／数据库／端口，不暴露 HTTP 管理诊断接口。普通网页管理员角色不因此获得他人卡片或文件内容。

默认仅写 stdout；`--json` 输出带 schema_version、时间、环境标识、检查范围、测量区间、样本数、阈值、结果和建议的结构化报告。`--deep` 增加文件 hash 核验；`--output` 或 `--record` 明确选择后才把脱敏报告／容量样本写到受限 ops 目录。脚本不创建媒体目录、不删除、不重建缩略图、不写库、不修改 ACL、不恢复、不迁移、也不探测外部网络。配置／权限失败属于检查失败，不输出凭据、卡片正文、作者或图片内容；默认仅给问题数量，详细项用附件 ID 和问题代码。

| 指标 | 数据来源与口径 | 默认判断 |
| --- | --- | --- |
| 图片体积和数量 | 原图、缩略图分别统计实际落盘与数据库登记量；列出已引用、未引用 ready、uploading、failed、孤立文件 | 单纯达到 50 GiB 提醒评估，不判定必须迁移 |
| 磁盘／inode | 媒体所在卷总量、使用量、可用量；ops／备份同卷时计入总占用；inode 仅支持的平台输出 | 70% warn，80% critical；Linux inode 同档建议 |
| 增长和可支撑天数 | `--record` 样本的真实目录净增长；至少 7 天有效观测，最多使用最近 30 天；另列成功上传量，不伪装为净增长 | 预留 max(总容量10%, 5 GiB)；正增长时 (可用−预留)/每日净增长，低于90天 warn、30天 critical |
| 文件完整性 | 默认核对登记 ready 文件存在及大小、失联记录、未登记文件、过期 uploading（24小时）；deep 比对 SHA-256 | 已引用原图缺失／损坏 critical，缩略图缺失、保留未引用文件、陈旧 uploading warn |
| 请求表现 | 读取受限本地媒体遥测；按 upload／thumbnail／original 分开统计请求数、5xx／传输失败、字节和服务端完成耗时 P95 | 最近24小时，至少100个已完成缩略图样本且 P95>1秒 warn；失败率>1%且至少100个请求 warn |
| 带宽 | 遥测统计实际响应体字节，不含协议开销；按5分钟桶计观察吞吐。仅显式提供可用带宽时计算比例 | 连续3个完整桶>50% warn；未配置分母时利用率 unknown |
| 备份／恢复 | 读取指定备份和演练目录的有效清单，区分数据库-only及带附件；报告最近完成时间、耗时及核验结果 | 最近联合备份超过24小时 warn；最近成功演练恢复耗时超过2小时 warn；无记录标 unknown |

增长为零／负值时预测返回不可估计，不输出无限天数；不够7天、遥测缺失或保留窗口不完整时返回 null＋原因，报告覆盖期和 completeness，不用0填补。计时与采样采用 UTC，文本显示 Asia/Shanghai；避免本机时区影响日报范围。

媒体请求遥测使用服务端响应完成／断开时的耗时及实际发送字节，写共享有界滚动 JSONL 文件（拟每文件 5 MiB、总计最多6个），通过线程锁与平台原生进程文件锁保护写入和轮换，重启不产生无限旧进程文件；诊断读取时取得同一锁形成一致观测，标明保留覆盖期。字段仅包含时间、进程实例、请求类别、状态、字节、耗时和传输结果；不包含 Cookie、请求体、URL、附件／用户 ID。原始遥测是运行时写入，诊断本身只读且不创建锁文件。遥测故障不让图片保存失败，诊断显示 unavailable；文件轮换只作用于遥测，不清理业务图片。

这里的服务端完成 P95 不能替代此前讨论的浏览器缩略图端到端 P95，报告必须明确标为服务端测量。浏览器真实体验通过人工网络条件验收；第一版不实现 RUM。请求样本不足不会自动判慢或判健康。

退出码：0=所有要求检查完成且无预警；1=存在 warn 或有指标未知；2=存在 critical（如已引用原图丢失、空间不足预留）；3=配置／身份／权限或依赖错误导致检查未完成。严重问题优先级高于未知；文本和 JSON 返回同一结论。检查期间并发上传形成的暂态文件用状态和年龄区分，未知文件不直接判为需要清理。

替代方案为新增监控平台或定时通知；用户需要的是脚本排查，当前日志＋按需 CLI 足够，且不增加常驻服务。阈值可通过 CLI 配置，建议只引导扩容、备份、排查带宽或评估对象存储，不自动执行这些动作。

### 7. 同快照备份与独立媒体恢复

扩展现有本机 `backup-db.cmd` 和 `db_backup.py`，生成 `selflore-backup-v2`：现有数据库 dump／signature，加附件清单、原图／缩略图副本、hash、字节数、统计和耗时。附件列表与 pg_dump／signature 来自同一导出快照，包含所有该快照登记的 ready 附件（含归档、回收站、未引用 ready），不扫描拷贝任意文件或上传中的 staging。文件不可变且无永久清理，因此快照后新增文件不影响本次完整性，移除卡片关联也不导致文件丢失。ready 文件缺失或 hash 错误时不写成功清单。

图片和 dump 复制期间为完整备份包维持受限权限。验证路径限定包内相对键，拒绝绝对路径、..、符号链接／重解析点及重复键；备份目标不在源 media／ops 中，避免递归复制。旧 v1 备份只有在清单与 dump 确认无附件表时才按旧语义恢复，不把新库缺少附件的 v1 伪包判完整。历史 v1 验证逻辑保留，v2 为新数据推荐格式。

演练沿用新建6179私有实例，同时创建独立的私有媒体和ops目录；恢复核对附件元信息、关系和文件 hash，并以 app／本人认证读取原图及缩略图，记录原始缺图故障。完成或失败只停止所属隔离实例，不覆盖日常库或媒体目录。报告记录总耗时及 restore_started_at／restore_completed_at，供诊断使用。
实际演练发现PG18在dump恢复时会展平0004用户名检查的嵌套AND。签名比较仅对该约束两个完整、精确且等价的已知表达式归一化；不移除任意括号，不忽略边界、正则、其他约束、对象所有者或授权变化。旧备份原始签名保留，不改写历史SQL。

现有自动备份仅开发库，不能隐式改成生产工具。Linux 正式发布文档补充显式生产联合备份步骤：管理员短暂停止应用写入后 pg_dump，并用同一媒体清单打包原图和缩略图、校验完成后恢复服务；若失败保留旧应用且不得激活。本轮实施验收仅本机／隔离环境，不连接生产服务器；生产步骤需以后实际演练才能宣称验证。

### 8. 环境配置与权限

媒体未配置时保留健康检查和已有文本功能，资料摘录可用；上传／已登记图片读取返回明确的 storage_unavailable，而不是 SPA HTML 或虚假成功。配置后缺目录、错误标识、不可读写目录需明确提示并在发布预检阻止启用图片功能。上传遇磁盘不足正确失败，并报告已完成文件的状态。

Windows 显式 ConfigureMedia 设置 root 并创建仅当前用户与 SYSTEM 可访问的媒体／ops 目录；只修改指定新增目录，不递归改已有任意路径 ACL。Linux 管理员预建 selflore 所属0700目录，服务 `ReadWritePaths` 精确允许这两个路径，保留 ProtectSystem=strict、NoNewPrivileges 等配置；重启前核对。备份读权限由管理员按运维步骤授予，不扩大网页账号权限。

本项目维护文档记录配置、启动、检查、备份、恢复和对象存储评估方式；不注册 Start Tab 新应用、不修改个人全局能力。诊断命令在当前项目即可执行，Linux 核心 CLI 不依赖 PowerShell。

## Risks / Trade-offs

- [文件系统与数据库无共同事务] → 上传状态、不可变键、先完成文件再 ready、卡片关系原子提交及只读一致性排查；不中断已有卡片保存语义。
- [首版保留所有已完成附件导致体积增长] → 单文件／像素／每卡限制、容量报告与陈旧未引用统计；永久清理另行设计。
- [本地磁盘损坏会丢图] → v2 联合备份及实际恢复演练；同盘备份只能提供回退，异地备份由维护步骤提醒，未完成不宣称容灾。
- [旧应用不认识 reference] → 前后端配套发布；已有资料后不自动回退至两类卡片旧程序，不删除新数据来恢复兼容。
- [滚动遥测缺少完整一天／浏览器网络不可见] → 报告实际覆盖期、样本数和服务端口径，缺测输出未知，浏览器体验另行验收。
- [诊断扫描大目录或 deep hash 占用磁盘] → 默认仅元信息检查，deep 显式启用；支持扫描预算／超时，部分扫描输出 unknown，不能判全部通过。
- [保留原始图片可能含 EXIF] → 明确原图保留行为，缩略图移除 EXIF，默认私有读取，未来分享另行处理。

## Migration Plan

1. 先在明确的一次性6179库与临时媒体目录验证；在当前最高编号之后新增迁移（目前拟0005），不修改0001–0004。扩展 cards／topics 类型及内容约束、附件表与延迟关联约束；新增字段默认 NULL，保留稳定 ID、原关系、复习状态和旧请求默认行为。
2. 按版本补齐最小 app 授权；更新本地启动表检查、新库和历史有数据库迁移测试。表、授权与迁移账本保持单事务。
3. 构建与测试后暂存新版；日常环境启用前完成现有数据库备份，显式配置媒体／ops目录并追加迁移。生产保留独立授权、人工联合备份、迁移后激活流程，不由程序启动自动迁移。
4. 用缩略图／原图、资料引用、三类合集、复习排除、游客隔离、监控异常样本和v2恢复演练验收；确认程序重启／release切换后原图不丢失。维护说明同步更新。
5. 新资料未创建前可回退旧应用但保留增量结构；一旦有reference或附件，回退仅选择能识别新数据的版本，否则保持新版并修复／关闭上传入口。禁止自动down迁移和删除资料或媒体来回退。
发布脚本无法直接读取数据库内容来证明回退安全，因此采用保守的能力标记：新包携带reference-v1，自动回退仅允许上一包具有相同标记；缺失或不同则返回失败、保持新指针，交由管理员核对实际数据后处理。此保护在隔离发布目录与模拟服务／网络操作中验证，不代表生产发布或版本探针已经实测。
