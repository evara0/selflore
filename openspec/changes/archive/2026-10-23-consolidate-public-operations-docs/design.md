## Context

现有 project-overview 规格已要求公开说明完整且链接有效，不需要新增行为要求。新 README 是产品入口，其他13份当前 Markdown 仍混有早期概览、验收数字和固定本机路径。既有生产验收已另有记录，本次不通过连接生产确认文档。

## Goals / Non-Goals

**Goals:** 每类信息明确一份主文档；当前操作不依赖历史“本次”叙述；保留凭据隔离、测试库、媒体完整性及回退约束。

**Non-Goals:** 不变更运行逻辑、迁移SQL、目录、发布工具、前端命名或自动测试配置；不增加协作入口、许可证和CI。

## Decisions

- README 为产品与技术概览唯一入口；PROJECT_OVERVIEW 没有当前可点击入链，可删除。历史变更中对该文件的文字引用保留，不能改写当时事实。
- 维护卡遵循既有模板但缩短内容，用操作表和链接取代重复教程，status 描述本次核实范围，生产验证结果只链接到有日期记录。
- 固定 Windows 启动文档统一使用仓库根相对路径和6171端口；通用数据库／认证例子保留5432，但清楚说明如何选择。媒体路径改成仓库父目录的示例，不绑定维护者盘符。
- DATABASE_SETUP 负责首次建库与角色，CARD_MIGRATIONS 负责完整顺序清单、升级和不可变机制；不在其他文档重复版本链。
- 历史验收片段先按原文迁入本变更 historical-validation.md，注明来源提交、原对应变更及过期语境；不重写已归档工件，也不把历史结果当成本次测试。
- 备份文档负责备份／恢复行为；媒体文档只保留配置、诊断与部署前提，链接备份文档。公共测试与维护者仅本机门禁明确分开。

## Risks / Trade-offs

- [去重误删必要步骤] → 历史内容先保存，关键命令和安全边界逐项对照源码；验证链接和章节锚点。
- [命令可读但未在新环境运行] → 文档静态检查代替业务环境启动，交付中明确未演练新安装，禁止声称命令运行已通过。
- [旧变更仍含过时表述] → 历史记录保留日期与基线，不对历史提案做全仓替换；当前公开说明单独核查。
