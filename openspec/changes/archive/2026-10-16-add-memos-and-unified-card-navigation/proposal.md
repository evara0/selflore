## Why

现有「知识／观点／合集／我的」将两类内容放在一级导航，却没有快速记录备忘、待办和待学清单的位置。直接新增第五个主导航会挤占移动端空间，需要在维持四个主入口的同时，将内容浏览与备忘执行分别组织。

## What Changes

- 桌面与移动端统一为「卡片／备忘／合集／我的」四个主导航；保留移动底栏中央的新建动作，不增加第五个主页面。
- 卡片页提供「全部／资料／事实知识／观点」筛选，全部仅聚合既有三类内容；保留观点的主题、关联阅读与事实知识的复习能力，并记住本人最近使用的类型筛选。
- 新增备忘卡，内部支持普通文字和勾选清单；提供全部、随手记、清单及跨清单未完成事项视图。待办和待学是清单用途，不新增卡片类型或主导航。
- 支持清单条目添加、编辑、删除、排序、完成与撤销完成，条目可关联本人已有卡片；备忘卡可被引用、加入合集、归档和移入回收站。
- 备忘不强制分类、标签或来源，不进入知识复习；创建、修改和勾选备忘不计为知识掌握或学习连续天数。待整理、事项完成、复习调度分别保持独立。
- 保留旧知识、资料、观点详情及筛选链接；新增结构通过增量迁移交付，覆盖权限、修订冲突、游客只读、备份恢复及发布兼容性。
- 本次仅建立规划。链接来源自动补全、OCR、AI 推荐、截止时间、通知提醒、重复任务、子任务和协作不在范围内。

## Capabilities

### New Capabilities

- `memo-cards`：普通备忘、结构化清单、条目完成及关联、未完成事项汇总与备忘搜索。

### Modified Capabilities

- `card-workspace`：四个主入口、统一卡片浏览、备忘入口、新建及旧路由兼容。
- `card-library`：第四类备忘身份、内容校验、分类与检索边界、清单修订和恢复。
- `card-collections`：支持备忘成员及只读清单翻阅，增加备忘类型数量。
- `opinion-linking`：稳定引用扩展到备忘及清单条目，保留关联来源与反向链接。
- `knowledge-review`：明确排除备忘与清单事项，不将完成事项视为学习评价。
- `personal-home`：备忘独立计数及活动，与知识统计、学习日历分开。
- `guest-demo-workspace`：四入口演示、备忘及清单只读交互、认证隔离。
- `card-schema-evolution`：备忘和条目增量结构、同用户约束、旧请求兼容及发布能力标记。

## Impact

- 前端：`apps/web/src/App.tsx`、知识和观点列表、编辑与详情、选择器、合集、个人主页、`lib/workspace.tsx` 和 `lib/demo.ts`；复用现有 React Router、TanStack Query 和 Markdown 渲染。
- 后端：`apps/api/app/schemas/workspace.py`、`routers/workspace.py`、卡片、合集、活动和复习服务；新增备忘条目服务及汇总查询。
- 数据库：在现有 `0005_reference_media.sql` 之后追加迁移，扩展卡片类型并增加备忘形式、清单条目及条目关联；不改写历史迁移，不转换已有内容。
- 验证与运维：扩展 pytest、Vitest、Playwright、迁移和备份恢复演练；更新卡片结构能力与相关发布兼容检查及维护说明。本方案不要求新外部服务或运行时依赖。
