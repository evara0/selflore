## Why

SelfLore 当前已有账号、会话、数据库初始化及版本迁移，但四个导航页仍是占位视图。用户已确认四页 UI 设计，需要将事实知识、观点、合集翻阅和个人主页形成一致的前端、API 与数据库方案，为完整实施提供可验证的边界。

## What Changes

- 按已确认的设计建立「知识／观点／合集／我的」四个导航页、稳定 URL 和正式新建入口，保留已有账号及管理能力。
- 建立统一的个人卡片库，支持知识问答、填空和原子观点，以及分类、标签、来源、搜索、收藏、编辑和回收站。
- 知识卡片通过独立的复习单元与 FSRS 调度提供主动回忆、答案揭示和四档记忆评价；观点通过稳定引用、显式链接与反向链接组织思考。
- 合集引用已有卡片，可混合两种类型，提供排序、目录、顺序／随机翻阅；显示答案与切换卡片分别处理。
- 个人主页提供资料、真实积累统计、近期记录、学习足迹和置顶合集；第一版全部个人内容保持私有。
- 在现有 PostgreSQL 数据库内通过新的版本迁移增加业务表、约束、索引和必要授权；保留现有账号、会话及全部数据。空库使用相同迁移链初始化，不提供清空重建操作。
- 补齐并发、幂等、用户隔离、数据库升级演练和四页联调验收任务。

## Capabilities

### New Capabilities

- `card-workspace`：四页导航、响应式布局、正式新建流程和页面状态。
- `card-library`：统一卡片、分类标签、来源、搜索、生命周期、并发与所有权。
- `knowledge-review`：问答／填空复习单元、队列、FSRS 状态和评价历史。
- `opinion-linking`：原子观点、稳定引用、关联及反向链接。
- `card-collections`：混合卡片合集、引用成员、原子重排和翻阅。
- `personal-home`：个人资料、积累统计、近期活动、学习足迹及置顶合集。
- `card-schema-evolution`：业务表增量建表、同源空库初始化、历史保留、权限与迁移验证。

### Modified Capabilities

无。主规格仅有仓库基线；已有账号与数据库能力仍位于独立 change 中，本变更接续其现有实现，不复制或重定义认证规格。新的正式新建流程替代旧 change 中的新建占位行为；四页中文导航替代原型英文名称。

## Impact

涉及 `apps/web/src` 的页面、共享组件及数据访问，`apps/api/app` 的业务路由／服务／查询与 `apps/api/migrations` 的后续 SQL，以及前后端测试和运行说明。计划补充 React Router、TanStack Query、Markdown 安全渲染和 FSRS 普通调度依赖，沿用 React／TypeScript／Vite、Python／FastAPI／psycopg 与 PostgreSQL 18。数据库继续使用现有可校验 SQL 迁移机制，明确记录与早期 Alembic 技术设想的差异。

最初规划阶段不执行数据库连接、迁移、清理或生产发布。后续已实施业务功能并按用户授权完成开发库迁移，生产未操作。2026-10-08归档核查发现移动底栏中央新建缺口，后续按用户要求完成任务15.1及触控验收，44/44项完成，同日按用户要求归档。已确认视觉参考位于 `docs/design/card-navigation-v1/`；其示例数字不作为真实业务数据。
