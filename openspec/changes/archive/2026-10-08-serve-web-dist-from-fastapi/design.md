## Context

见 `proposal.md`。当前 `apps/api/app/main.py` 只注册 `/api/health`；Vite 构建输出位于相邻的 `apps/web/dist/`，该目录受 Git 忽略。后端在没有构建产物时也必须保持可用。

## Goals / Non-Goals

**Goals:**

- 运行后端即可从同一端口访问已构建的前端，并保留客户端页面路由。
- 将 API 路径与静态资源的 404 语义保持清楚。

**Non-Goals:**

- 不在后端启动或构建前端，不增加 Node.js 运行时。
- 不设计容器打包、Caddy、域名或生产发布流程。

## Decisions

### 在 API 路由之后挂载构建目录

应用从仓库内 `apps/web/dist/` 查找构建产物；只有 `index.html` 存在时才挂载静态服务。这样无构建产物时仍可启动健康检查。挂载放在 API 路由之后，避免覆盖已定义的 API。构建完成后重启后端以加载产物。

### 为页面路径增加受限回退

使用 FastAPI 所依赖的 Starlette 静态文件服务提供文件；当请求是不存在的页面路径时返回 `index.html`。`/api`、`/api/*`、`/assets/*` 和带文件扩展名的缺失路径不回退。静态文件服务负责限制路径在 `dist` 内，不自行拼接未经校验的文件系统路径。

相比直接让所有未知路径返回首页，这能避免把 API 错误或资源缺失伪装成 HTML 成功响应。相比仅用静态服务的 HTML 模式，受限回退支持将来的客户端路由。

## Risks / Trade-offs

- [后端启动时无 `dist/index.html`] → 不挂载前端，API 正常运行；构建并重启后端后页面可用。
- [前端路由包含文件扩展名或以 `assets/` 开头] → 此类路径会返回 404；当前尚无正式页面路由，若未来需要，应在 UI 路由设计时调整规则。
- [前后端构建版本不匹配] → 本变更只处理本地挂载；生产发布应将前端产物与后端版本作为同一发布单元验证。

## Migration Plan

1. 在 `apps/web/` 执行生产构建。
2. 启动或重启 FastAPI；验证 `/`、静态资源、页面路径和 `/api/health`。
3. 回退后端代码即可恢复原有仅 API 行为；`dist` 仍是可重新生成的构建输出。
