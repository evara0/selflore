## Context

项目目前仅有版本控制与 OpenSpec 基线。此变更引入第一个可运行组件；它必须保持独立、无状态并受 `proposal.md` 与 `api-health-service` 规范的最小范围约束。

## Goals / Non-Goals

**Goals:**

- 在 `apps/api/` 建立由 uv 管理的隔离 Python 项目。
- 提供可重复的本地启动、测试和健康检查验证方式。
- 将依赖版本通过 `uv.lock` 固化，且不把 `.venv/` 纳入 Git。

**Non-Goals:**

- 不创建任何数据库、用户、认证、配置加载、业务路由、容器或部署资源。
- 不监听额外端口，且不引入面向生产的进程管理策略。

## Decisions

### 项目位置与环境管理

API 作为 `apps/api/` 下独立 uv 项目创建。使用 uv 创建并维护该目录的 `.venv/`、`pyproject.toml` 和 `uv.lock`；不会向全局 Python 安装项目依赖。

### 最小运行结构

使用 FastAPI 应用模块与 ASGI 服务器依赖。项目说明提供 `uv run` 的启动命令，绑定 `127.0.0.1:24566`；端口不硬编码进应用逻辑，便于测试客户端直接构造应用并由启动命令规定监听地址。

### 可验证的无状态响应

健康检查只返回稳定 JSON `{"ok": true}`。测试使用 FastAPI 的测试客户端验证状态码与完整响应体，无需启动实际网络服务器；另以 `uv run` 启动后请求固定地址完成烟雾验证。

## Risks / Trade-offs

- [端口 `24566` 被其他进程占用] → 启动命令会清晰失败；先检查并释放占用进程，不为本变更增加端口回退逻辑。
- [依赖解析差异] → 提交 `uv.lock` 并在验证使用 `uv sync --frozen`。
- [健康检查范围被误扩展] → 以规范限制为单一端点，额外能力另行提出 OpenSpec 变更。

## Migration Plan

这是新增且无已有服务的组件。实现时创建 uv 项目和锁文件，添加最小应用与测试，使用 `uv sync --frozen`、测试命令和对 `127.0.0.1:24566/api/health` 的请求验证；失败时删除尚未提交的新增 API 文件即可恢复到现有基线。
