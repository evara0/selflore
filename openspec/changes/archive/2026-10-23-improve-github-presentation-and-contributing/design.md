## Context

见proposal.md。已有README及分工明确的操作文档，`.github/workflows/ci.yml`可提供真实状态徽章；缺贡献文件与模板。`docs/`是私有忽略目录，旧截图存在旧导航，不能直接发布。当前`src/lib/demo.ts`提供完整的合成卡片、备忘和合集。

## Goals / Non-Goals

**Goals:** 访客能看见当前界面、了解许可并提交有用的反馈；贡献者沿现有文档复跑检查。

**Non-Goals:** 不接入新服务或表单处理后端，不增加依赖，不修改仓库在线设置，不作产品重构或发布。

## Decisions

- 公共图片放`assets/screenshots/`，不放行整个docs；保留PNG原图和小型来源README。使用当前前端构建、浏览器新上下文及只读认证替身触发原生游客演示，不访问真实数据库或用户会话。
- README采用实际工作流徽章及两张预览，不增加重复功能长文。截图说明版本及开发状态；截图不宣称已在生产部署。
- GitHub原生YAML问题／建议表单配短PR Markdown模板，不预设不存在的标签、项目、评审人或安全反馈渠道；保留普通Issue入口。
- CONTRIBUTING说明先讨论范围、fork／分支、按改动选择验证及提交评审。永久行为变化沿用OpenSpec；小文档勘误不强制建立无行为变更规格。现有文档保持启动及测试命令的单一来源。
- LICENSE从Apache官方`.txt`下载并核对完整字节，不改写授权文本；README明确Apache-2.0，第三方依赖及用户保存的资料继续适用原权利。不引入额外CLA或虚构NOTICE归属。

## Risks / Trade-offs

- [截图过期] → 记录输入提交、尺寸和演示来源，界面变化时同步更新；本次生成后实际查看两张图片。
- [模板只在推送后生效] → 本地校验YAML结构、链接和内容，准确区分未提交／推送与GitHub实际生效；不发测试Issue或PR。
- [截图体积] → 仅两张PNG，不加入无关证据、浏览器配置或旧设计图。
