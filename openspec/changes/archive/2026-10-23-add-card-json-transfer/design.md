## Context

动机见 proposal.md。当前 `schemas/workspace.py` 的 CardCreate 要求 UUID client_request_id，使用 extra=forbid 和类型组合校验；`routers/workspace.py` 提供单卡创建、分页摘要、详情、独立链接操作，统一依赖会话／Origin／CSRF。`services/cards.py` 的 relations 在创建时立即查目标，不能直接循环调用来处理前向／循环引用；create_card 同步学习单元和活动。附件 upload 自行提交数据库并发布不可变文件，不可直接嵌入批次事务。清单已有三列含隐藏值，标签按 NFKC 加首尾去空白归一。

## Goals / Non-Goals

**Goals:** 使用独立交换 DTO，在同账号及跨账号／实例保持内容语义，提供机器可用格式和普通用户可用入口，以集成往返证明完整性。

**Non-Goals:** 不覆盖既有卡片，不以标题判重，不导入外部网页，不调用 AI API，不兼容 Anki；不替代数据库灾备。合集编排、账号资料、复习历史和活动日志不在 v1。导入创建新 ID、编号、修订和创建时间；历史卡片时间可列为只读来源元数据，不冒充新卡片时间。

## Decisions

### 1. 独立 v1 契约

新增 `schemas/card_transfer.py`，发布 `docs/card-transfer/v1.schema.json`、中文说明、六种形式示例及 AI 提示词。Schema 使用 JSON Schema 2020-12；生成静态 Schema 并校验与后端模型一致。文档、示例与Schema同步携带在 app/transfer_docs 中供公开只读接口下载，通过字节一致性测试避免发布包缺少根目录docs。条件和引用等语义仍由服务校验，文档明确 Schema 不是唯一校验层。

顶层为 `format: selflore.cards`、`version: 1`、`cards`、可选 `assets` 和只读 `export_info`。每卡具有唯一 key、kind、对应 form/memo_format、内容／来源字段、字符串 tags、lifecycle（默认 active）、收藏与整理状态。条目有局部 key、text、extra_values、is_completed、可选 completed_at、target_keys；无有效完成时间的已完成 AI 条目由服务器记录导入时间。手工链接使用 link_keys。内部 Markdown 引用用 `[[card:<key>|可选标题]]`；key 限制为1–80个 ASCII 字母数字、下划线和短横线，避免分隔符歧义。导出把已识别 UUID 引用转为这种标记，导入再转换；使用现有 Markdown 引用解析边界，代码块等非引用原文保持。拒绝未映射的内部 UUID 引用，外部 HTTP(S) 链接保持文字，不联网。

asset 元信息包含 key、相对 path、sha256、bytes、mime_type；卡片关联使用 asset_key 与现有图注字段。无图片文件直接使用 JSON；有图片只提供 ZIP，根 manifest.json 使用同一格式，media/ 下放原图。避免在 JSON 中使用巨大 base64 或依赖失效的鉴权 URL。缺图不降级为成功备份。

### 2. 预检和提交共用校验

新增 `/api/card-transfer/validate`、`/import` POST multipart 接口，均复用会话和写请求安全检查。validate 不写业务数据，返回规范化摘要、数量、排除项与 errors（card_key、path、code、message）。import 提交同一文件、expected_digest 和客户端生成的 batch_id；重新校验，不保存有过期风险的预检对象。

默认每次最多2000张卡、JSON 32 MiB、ZIP压缩及总解压各512 MiB、ZIP成员数10001；单图及图像像素／格式复用媒体限制，累计处理字节受预算限制。导出超限明确失败，不截断；文档列出限制，未来再增加分卷。不把此版本宣传为任意规模备份。

### 3. 新身份、关系两阶段和批次幂等

新增 owner-scoped `card_import_batches`，唯一(owner_id,batch_id)，记录规范化 manifest 与原图摘要组成的 digest、完成结果映射与统计；不存原始正文副本。事务内锁定该键，同摘要返回原结果，不同摘要409。语义摘要忽略 JSON 空白和对象键顺序，保留数组顺序及全部语义字段；ZIP容器元数据不参与摘要。

通过一次外层事务分配所有新卡片、条目及附件身份，先插入节点再解析引用、条目和标签关系；复用现有校验与无提交内部写入，避免逐卡 HTTP 循环和 create_card 的提前引用查询。名称按现有标签规则复用／创建，统一标签写入不提交旧 topic_ids。条目迁移专用路径可恢复旧类型关系，但不修改普通编辑器新增知识关系的限制。知识初始化学习单元；活动按新创建语义产生，不重放历史完成／复习事件。生命周期在事务内恢复，避免归档和回收站卡进入队列。

### 4. 媒体事务边界

解包只按允许成员读取到应用临时目录；拒绝绝对路径、反斜杠歧义、..、符号链接、重复路径和不允许成员，流式累计实际解压字节。校验原图摘要、格式和尺寸后重建缩略图。预检结束清理临时文件。提交时先发布经过校验的不可变文件，再在业务事务内登记 ready 附件及卡片关联，不调用会自行 commit 的 upload。失败不留下可见业务对象；尝试专属未登记文件进入可追踪恢复记录，不删除或改写任何已有 ready 文件。重试必须能恢复／清理本次临时产物；模拟磁盘失败和进程中断验证这一边界。

### 5. 一致性导出

新增 `GET /api/card-transfer/export?format=json|zip`，仅本人全类型和全生命周期。使用只读 REPEATABLE READ 快照收集完整字段、条目、手工关系、内联引用及实际关联 ready 附件，禁止使用 list_cards 摘要。原图不可变，在有界临时文件中完成哈希校验与打包后才返回下载，失败返回结构化错误。JSON请求遇到图片返回需要ZIP错误，不丢附件。包含 export_info 的范围、数量、排除项及生成时间；无图片也允许ZIP。响应 private,no-store；日志不记录原始内容。

### 6. 个人页入口

在 `features/profile/Profile.tsx` 增加独立导入导出区，延用现有请求／错误处理，提供格式文档及模板下载。选择文件→预检摘要／逐项错误→明确确认→映射及数量结果；换文件立即清空旧预检与批次键，网络重试复用原键，成功后再次复制须显式开始新批次。导出区域简要提示包含归档与回收站，范围、排除项、文件限制收进按需展开说明，默认推荐ZIP；无图可选JSON。不修改全局导航和主题。

## Risks / Trade-offs

- [单批限制不适合大型库] → 超限明确报错不生成残缺成功文件；后续分卷需要独立规格。
- [跨文件和数据库无法同事务] → 不可变发布、业务事务原子登记和尝试恢复记录；不能声称文件系统绝对回滚。
- [重复导入被误解为更新] → 预览说明仅新建；幂等只覆盖同批次，不进行内容相似度合并。
- [格式演进偏离业务校验] → 共享规则和契约样例测试；未知版本拒绝，不猜测转换。
- [内容包被当作全站备份] → Schema、界面和文档都列排除项，既有数据库媒体灾备流程保留。

## Migration Plan

实施时新增下一号 SQL 迁移，建立导入批次与必要尝试恢复记录，沿用账号隔离和应用角色授权。先在一次性隔离库验证升级和重复执行；不访问日常6171数据库。旧单卡 API 不变。发布／真实库迁移需另外授权；回退应用版本可保留新增表，不删除已导入卡片或媒体。实施在独立 worktree 内进行，不自动执行真实业务库迁移或发布。

## Follow-up: 文件选择按钮

用户指出原生“选择文件”按钮与整体风格不一致。保留原生文件输入及其键盘和文件选择语义，用局部 ::file-selector-button 样式复用现有按钮的字体、配色、边框、圆角及悬停；处理禁用和焦点状态，不影响全局上传控件。

## Follow-up: 精简说明

用户要求减少无关介绍和小字。默认面板只保留文件选择、预检／确认、预检数量、导出格式与操作；仅提示导出含归档和回收站。格式文档、示例、Schema、大小限制、完整备份边界和重复导入规则放入原生details／summary，可键盘展开。预检数量及新建语义合并显示，移除重复状态文案，不缩小文字来压缩内容。
