## Context

动机与范围见 [proposal.md](proposal.md)，视觉契约见 [默认主题规格](specs/default-ui-theme/spec.md)。本变更跨多个前端模块，需要统一主题与卡片身份接入设计。

当前 React 前端由 `App.tsx` 维护四页导航、移动固定底栏和认证弹窗，`index.css` 定义全局基础样式，`App.css` 集中定义业务组件样式。颜色大量硬编码，`.tag:nth-child(2n)` 会给同一卡片的标签引入另一色系；复习评分也使用独立四色样式。知识列表的 `Flashcard`、观点列表、`CardDetail`、合集 `reader-card`、复习 `study-card` 分别渲染同一内容，尚无共享墨色映射。合集已有 `sage/clay` 封面色和 `curve/lines/radial` 封面样式。所有卡片已有稳定 `id`，复习单元可通过 `unit.card.id` 获取原卡身份。

现有规格要求保留移动固定底栏中央新建、真实内容隔离、答案默认隐藏、混合合集及正式复习行为。设计预览用于确认视觉方向，其手机顶部导航、默认事实知识筛选、编号排序、可直接切换收藏等简化行为不是业务变更。

用户于 2026-10-13 确认本变更目录中 `design-reference/` 的独立预览和四张截图。它们已按原文件复制并核对 SHA-256 一致；实施不得覆盖这些已确认的参考图。

## Goals / Non-Goals

**Goals:**

- 用一套可维护的基础令牌、卡框样式与稳定墨色映射承载已确认的视觉，避免各页面继续独立硬编码。
- 相同卡片跨知识列表、观点列表、详情、合集与复习拥有连续的视觉身份。
- 在实际数据、长内容、附件和现有移动导航下还原参考稿的纸张、排版、边框及留白。

**Non-Goals:**

- 不将独立 HTML 预览替换为应用实现，不接入预览中的硬编码示例或本地模拟业务逻辑。
- 不增加主题选择器、暗色主题、自定义卡片配色、字体下载、图片重绘、API 或数据库字段。
- 不重构数据查询、认证、复习调度或路由，不修改现有封面选项的持久化值。

## Decisions

### 1. 全局基础令牌与局部卡片墨色

在 `index.css` 定义纸张、背景、正文、中性次级文字、分隔线、四种墨色、淡墨、焦点和状态令牌，`App.css` 使用这些令牌重新组织现有样式。现有 `--ink`、`--muted`、`--border` 等变量保留兼容映射；需要局部适配的卡片与子组件从卡片容器继承局部墨色。

设计起点：纸底 `#f7eedc`、页面底 `#eee5d3`、中性正文 `#494338`、次级文字 `#766b5b`、规则线 `#cbbfa9`、紫 `#634779`、蓝 `#325c83`、绿 `#4d703d`、赭橙 `#a65d2b`。淡墨只用于浅底、次要框线与装饰，标签和正文不因降低透明度失去对比度。使用实际背景计算对比度，必要时微调色值；控件边界可使用比普通分隔线更深的令牌。

采用系统字体栈：英文品牌与编号用 Georgia，中文标题用本地宋体及 serif 回退，正文继续使用现有系统无衬线字体。无需网络字体，跨系统允许字形差异，保持字号、层级与换行质量。

替代方案：在旧样式末尾大量添加覆盖容易留下优先级冲突；为每页复制主题容易破坏一致性。因此直接整理现有规则和断点，不引入主题框架或第三方组件库。

### 2. 从稳定卡片 ID 计算墨色

新增纯主题工具，例如 `apps/web/src/lib/theme.ts`，使用固定顺序的四种墨色与固定的 32 位 FNV-1a 字符串散列，将规范化的卡片 ID 映射到一个墨色名。映射不依赖类型、标题、数组索引、当前日期、随机数或复习单元 ID。同一工具供所有展示组件使用，通过语义类或 `data-card-ink` 将颜色传给样式；空 ID 仅给未保存编辑器提供固定默认色。

接入位置：知识 `Flashcard`（含资料分支）、观点列表条目、`CardDetail`（含紧凑详情）、合集当前成员、正式复习的 `unit.card`。资料说明、来源、普通 Markdown 链接和多标签继承同一墨色；关联卡片若作为独立卡片展示，使用自己的身份映射。业务状态通过现有文字和图标继续标识，错误反馈可以使用必要的语义色。

固定 ID 映射免除 API、迁移及首次加载时配色闪动；列表排序改变或卡片出现在不同合集不会变色。实际业务卡片无需与示意稿中某个示例编号的墨色逐一对应，四种色值、单卡一致性与整体节奏应与确认稿一致。避免使用 `nth-child` 配色或将墨色按卡片类型固定绑定。

### 3. 可复用卡框与克制的纸纹

共享印刷卡框规则应用于真实内容卡片：约 3px 外框、内缩约 5px 的 1px 内线、方正角标与细几何收边，极小圆角或直角、轻微纸张落影。使用 CSS 或现有代码原生几何素材实现，不生成装饰图片。伪元素设为非交互且不覆盖内容，不让卡框变成可点击控件。

卡片容器保持弹性高度，答案展开和长文阅读推动页面布局；只有现有摘要允许截断。纸纹为静态低对比背景，限定在背景层，不给整个卡片加滤镜。标题偏宋体书册风格，正常正文对比清晰，桌面保留侧栏和三列卡片的节奏。标签移除奇偶双色规则，链接用下划线或图标表达可操作性。

复习评价位于当前卡片内时沿用该卡的墨色，以评价文字、边界、按压和禁用状态区分四档，不把整张卡片切换为评价颜色；时间间隔与现有提交行为保持可用。辅助控件用中性底与紫色主操作，不给所有表单面板增加厚装饰。

### 4. 合集色值兼容与图片原色

现有 `sage` 映射到印刷绿，`clay` 映射到赭橙；`curve/lines/radial` 分别以线性拱形或同心结构、棋盘或交错线、放射几何呈现。复用 `Cover` 以统一合集列表、侧栏和个人主页置顶入口；允许按尺寸简化纹样。合集列表标题、说明与封面组成同一单色卡面。`cover_color` 的未知值使用固定的合集 ID 回退色，保留已有值并避免崩溃。

翻阅成员继承原卡的 ID 配色，而非封面色。`PrivateImage`、附件缩略图及原图继续按原比例呈现，保持所有颜色；图片放大对话框仅调整壳层主题。用户提供的八张参考插图不放入公开演示空间，也不成为运行时附件。

### 5. 以现有响应式行为承载新外观

沿用 `.desktop-nav`、`.mobile-nav` 和既有移动中央新建入口，不复制预览的手机顶部导航。桌面知识列表三列、平板两列、手机单列；观点详情延续移动独立阅读及返回，合集和辅助页面按现有内容适配。保持搜索、分类、类型、排序和分页入口，尤其不因稿中隐藏侧栏而移除手机筛选。

在 320、390、736、1024、1440 宽度检查工具栏、长标题、多标签、原图弹窗、登录／注册校验、四档评分和底栏安全区。可编辑字段在手机使用足够字号，装饰不缩小触控区域；固定底栏末尾留白应覆盖实际高度和安全区。保留清晰焦点、`aria-*`、原有图标及减少动态效果支持。

### 6. 实际界面验证与参考图对照

保留现有 `guest.spec.ts`、`mobile-create.spec.ts`、`reference.spec.ts`、`registration.spec.ts`、`workspace.spec.ts` 的行为语义；补充稳定身份配色和跨展示场景的针对性断言，不为低影响 CSS 逐条编写镜像测试。浏览器视觉验证输出到 `docs/design/default-letterpress-theme/implemented/`，包括四主页面、知识详情与答案展开、资料图片、认证／编辑、复习以及手机底栏。

演示视觉验证拦截认证 API，并确保没有额外业务请求；需要账号及复习队列的测试只运行明确隔离的 6179 数据库／24568 测试服务。既有 CSS 类若无需移除则继续保留，减少无关测试选择器变动。运行 `pnpm test`、`pnpm lint`、`pnpm build` 及相关浏览器用例，记录实际成功或失败，不能把预览检查视为正式应用已验证。

## Risks / Trade-offs

- [旧硬编码色遗漏] → 按主页面、辅助页面、媒体和状态逐项检查，统一令牌，审查标签、复习评分、Markdown、图注及伪元素的继承。
- [标题字体在不同系统有差异] → 使用系统回退，视觉验收关注层级、留白与可读性，不依赖外部字体可用性。
- [方正厚边框挤占手机空间] → 内容自适应高度，断点调整内边距与装饰，不裁切正文，不隐藏必要筛选与底栏操作。
- [卡片色被误认为状态] → 保留类型和状态文字；颜色仅作为卡片视觉身份；必要错误反馈独立表达。
- [参考稿包含简化业务行为] → 只复用视觉，不复用预览 JS、数据、默认排序、权限或答案状态；主规格继续约束实际流程。

## Migration Plan

1. 本轮保存规划与确认稿，不修改应用源码、业务数据库或发布目录。
2. 后续实施先接入令牌和统一映射，再逐页接入视觉并执行验收；无需数据库迁移或旧内容重写。
3. 构建与测试通过后交付应用截图，保留 `design-reference/` 作为确认基线；实际发布按后续明确授权执行。
4. 如需回滚，恢复本次前端修改并重建旧前端即可，卡片、附件、合集及学习数据不受主题变更影响。
