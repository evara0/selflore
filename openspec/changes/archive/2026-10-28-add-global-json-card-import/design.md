## Context

新建按钮统一进入 /new，现有 Editor 再选择卡片类型。POST /api/cards 接受 CardCreate，已有 CardContent 内容校验、清单多字段结构、账号隔离和 client_request_id 幂等创建。直接在前端复制所有规则容易产生差异；为首次生成文件的用户要求手工填写条目 UUID 也没有必要。

## Goals / Non-Goals

目标：全局入口；以 JSON 自带类别决定目标；文件与粘贴等价；先校验及预览，再确认保存；清晰错误、失败保留和重试；保留用户提供的三字段需求清单。

非目标：批量对象、合集、数据库备份恢复、外部图片抓取、导入后自动选取分类、创建标签、修改已有卡片和生产部署。

## Decisions

1. /new 与新的 /import 共享“新建方式”导航。桌面和移动全局新建均可到达；类别编辑器中不添加文件和 JSON 控件，保留既有手动新建体验。
2. 首版仅接受一份 JSON 对象。kind 必填；knowledge 的 form 为 qa/cloze，memo 的 memo_format 为 note/checklist。沿用 CardContent 字段名，未知字段拒绝，不把不支持的数据静默丢弃。省略 taxonomy_mode 时使用 unified，已有标签／附件／行关联 ID 在保存时继续由原有账号归属检查兜底，不自动创建关联对象。
3. POST /api/cards/import-preview 接受 json_text，要求登录、Origin 和 CSRF；限制为 1 MiB UTF-8，拒绝数组、JSON 语法错误、重复键和非 JSON 常量。复用 CardContent 校验；清单行仅在缺少 id 时生成稳定 UUID，已给定 ID 验证并保留。预览不写业务表、不调用外站。
4. 预览返回标准化内容。客户端在本次草稿中保存预览和新的 client_request_id，保存复用 POST /api/cards。相同输入重复预览复用已准备内容；保存失败重试沿用请求 ID 和行 ID；修改输入使预览失效，防止提交旧预览。
5. 显式确认后才创建，保存成功进入对应 /cards/:id 或 /memos/:id 并刷新缓存。未保存离开沿用现有保护，成功后解除。读文件／校验期间提供状态并禁用冲突操作，迟到响应不能写回已卸载页面。
6. 附加信息在预览显示；不将任意 JSON 当作完整备份，不接受 owner_id、顶层 id、revision 或 client_request_id 等非内容字段。Markdown 使用既有安全渲染，不自动下载外部图片。

## Risks / Trade-offs

预览仅证明内容结构有效，标签、已有附件和关联对象是否属于当前账号仍在实际保存中验证；失败保留原稿。跨页面刷新未保存内容仍会丢失，不将离开保护说成持久草稿。文件按 UTF-8 读取，BOM 可移除，不猜测其他编码。一份对象的范围避免批量部分成功和事务协议扩张。

## Validation

后端离线测试覆盖类型、规范化、大小、重复键、字段约束、鉴权和无写入；前端及浏览器覆盖全局入口、文件与粘贴、预览后修改失效、错误保留、失败重试、离开保护、登录门禁和类别跳转。使用真实预览 API 与合成创建替身补充浏览器契约验证；无业务数据库写入。构建、格式、lint、组件测试及 OpenSpec 校验；在 320、390、1280 像素实际查看导入、错误及三列预览截图，回看 /new 新导航布局。
