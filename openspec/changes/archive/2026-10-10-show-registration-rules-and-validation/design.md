## Context

第一版已完成字段规则、失焦反馈与提交保护。验收反馈要求同时放宽账号规则和减少重复描述。本修订复用现有实现，动机见 proposal.md。

数据库首个迁移对 app.users.username 存在旧的首字母限制。后端 normalize_username、validate_password 被注册、管理员创建账号、初始化管理员和修改密码共用；前端登录、管理账号和修改密码也有旧约束。它们必须同步，否则中文或数字开头账号无法注册或登录。

## Goals / Non-Goals

**Goals:**
- 将相同账号规则贯穿数据库、后端和所有账号表单，并保留既有账号兼容性。
- 每个字段同一时刻只显示帮助或错误，去除重复汇总。
- 用安全隔离的验证证明迁移和中文账号注册登录可用。

**Non-Goals:**
- 不调整唯一性、账号角色、限速、密码哈希、会话和注册开关。
- 不增加密码强度评分、验证码或用户名可用性预检查。
- 不自动执行开发或生产数据库迁移，不发布或归档。

## Decisions

### 对齐简化账号规则

用户名字符范围明确为 U+4E00–U+9FFF、ASCII 英文字母、数字、下划线、连字符，长度 3–32，不限制首字符。前端和 Python 使用相同范围，大小写仍由后端 lower 规范化。限制明确范围可避免不同运行环境对 Unicode 字母分类的差异，不采用任意非空用户名。

密码最低长度统一降至 8，最大 128 保持不变。前端继续沿用既有字符串长度方式，后端继续使用字符计数；此修订不额外改变已有 Unicode 非基本字符的计数差异。

新增不可变迁移 0004_relax_username.sql，替换 users_username_check，保留既有 varchar、UNIQUE 和账号数据。不修改 0001 的已执行校验和。SQL 用长度限制及禁止范围外字符表达规则，避免依赖 PostgreSQL 区间量词的字符排序行为。

### 减少同时可见的提示

有效或尚未交互的用户名、密码各显示一句简短提示；确认密码只显示字段标签。字段交互后无效时，错误文字替代帮助文字，使用稳定反馈 ID 和 aria-describedby，并设置 aria-invalid。

删除按钮附近汇总。禁用状态可由字段文字解释：字段尚未交互时有短规则，失焦后有具体错误。空字段首次打开不报错。沿用失焦标记、修正时更新及模式切换和关闭重置逻辑。

保留接口响应区域 role=status，用于服务器错误、成功消息和请求进行中反馈；不增加重复的状态区域。提交处理器保留统一有效性和进行中保护。

### 验证与兼容

同步前端登录和管理账号约束，原有英文账号仍可登录。使用后端纯函数边界测试和 TestClient 验证，数据库迁移在自行新建的临时 PostgreSQL 实例演练，验证旧账号保留、中文及数字开头用户名可插入，非法字符和重复用户名仍被拒绝。

浏览器测试继续拦截 API 验证界面反馈，在可用的临时后端增加真实注册登录验证。新截图存到 registration-feedback-v2，保留第一版截图供比较。

## Risks / Trade-offs

- [最低密码长度降低] → 仍保留密码哈希、登录限速与 128 位上限；不改变认证保护机制。
- [新前端先于数据库更新] → 发布必须先执行 0004 迁移，再更新后端和前端；旧规则账号均满足新约束。
- [SQL 与应用接受的字符不一致] → 测试相同中文、数字开头、长度边界和非法字符，真实 PostgreSQL 核对约束。
- [提示变短后未描述全部字符范围] → 常驻提示仅介绍主要条件，非法字符时显示“请用中文、字母、数字、下划线或连字符”。
- [密码 Unicode 计数的既有差异] → 本修订保持已有计数方式，服务端仍为最终校验依据。

## Migration Plan

先在临时实例验证全链与旧版本升级，再于明确发布时执行目标环境迁移、更新后端和前端、验证中文账号注册及登录。回滚应用时保留放宽后的数据库约束；已创建的中文账号需要新版本登录入口，不直接恢复更严格的数据库约束。当前实施阶段不连接实际数据库执行迁移。
