## Context

见 `proposal.md`。当前前端只有单个 React 导航壳层，移动底部“New”按钮没有点击行为；页眉右侧是静态状态文字。用户提供的图片呈现白底双边框账号面板、中文大标题、登录／注册标签、输入框及右下角提交按钮。

## Goals / Non-Goals

**Goals:**

- 在已有壳层中添加一致的桌面和移动端新建入口。
- 用可关闭、可键盘操作的弹窗呈现接近参考图片的账号表单。

**Non-Goals:**

- 不实现记录编辑器、账号创建、登录、会话或 API 调用。
- 不将参考图片中的其他品牌名称带入 SelfLore。

## Decisions

### 复用单个页面选择状态

“新建”作为现有占位导航的一个页面状态。只渲染一个按钮元素：桌面处于页眉，移动端通过响应式定位处于底部导航中央；底栏其他四个按钮分居两侧，为它留出点击区域。两种布局共用点击处理、选中状态和占位视图。新建视图显示尚未接入内容创建的说明，不伪装成可保存编辑器。

按钮在 DOM 中位于带背景模糊效果的页眉之外。桌面使用无滤镜的页眉外层定位到页眉操作区；移动端相对于视口固定到底栏中央，避免 `backdrop-filter` 祖先改变固定定位的参照范围。

### 使用原生 dialog 承载账号面板

用浏览器的模态 `dialog` 实现焦点限制及 Escape 关闭，并通过 React 状态同步打开、关闭与登录／注册标签。对话框视觉采用参考图的白底、细双边框、衬线中文标题和矩形表单控件，同时保留 SelfLore 品牌。整体收窄对话框、字号与控件尺寸；移动宽度下进一步压缩留白并允许内容滚动。

针对弹窗仍显过大的反馈，将桌面宽度上限进一步降至约 520px，移动端宽度上限约 340px，并同步缩小标题、标签、输入框和垂直间距。保持表单文字清晰、触控控件可操作，注册模式内容超出短视口时仍可滚动。

### 仅做前端表单反馈

按钮在必填项不完整或注册确认密码不一致时禁用。有效提交只显示“认证服务尚未接入”的提示，不触发网络请求，也不设置已登录状态。此行为使界面可演示且不会误导用户。

## Risks / Trade-offs

- [参考图与现有网格玻璃风格不同] → 将参考风格限定在弹窗内部，页面壳层只增加少量入口样式。
- [移动端弹窗高度超过视口] → 对话框设置视口内最大高度与内部滚动。
- [表单看似可用于真实登录] → 提交后明确显示尚未接入服务的状态。
